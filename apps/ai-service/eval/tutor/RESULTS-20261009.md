# Document AI assistant (Tutor): before and after adding Jev

> Measured on 2026-10-09 in the "A+ Python" group · branch `feat/tutor-jev` (backend, frontend) ·
> chat model `gpt-5-nano`, embedding `text-embedding-3-small`, Jev `jev-1.13.0`.
> Total OpenAI + Jev spend for all measurements, demos and debugging: about **$0.81** (cap $2).

## 1. Conclusions

- **Enable Jev for the Tutor**, with all 3 nodes (gate + rerank + sufficiency). The share of correctly handled questions rises from **91% to 95%** (528 runs). The gain comes from three measurable places:
  - **Out-of-scope questions are blocked before the LLM is called**: 58% → **100%** handled correctly. Without Jev, 3/12 runs had the LLM answer anyway (World Cup ×2, cooking pho ×1) and 2 more rambled. The gate wrongly blocked no valid question (0/114).
  - **Cleaner prompts**: 35% → **96%** of the passages put in the prompt belong to the right document, and LLM input tokens drop **54%** (3,721 → 1,728 per question).
  - **Single-document questions**: 94% → **100%**.
- **Latency does not increase.** Jev costs about 1 second per question (3 calls), but the LLM gets a shorter prompt. Measured interleaved under the same load: p50 **16.6 s → 14.5 s**.
- **Cost per question rises 46%** ($0.00054 → $0.00079): `gpt-5-nano` is so cheap that the Jev share ($0.00035/question, mostly reranking 20 passages) outweighs the LLM saving ($0.0001). At 1,000 questions/day that is about $0.25/day more. It can be reduced, see §10.
- **Fault tolerance as required.** Bad key and timeout: 147/147 failed Jev calls were logged and fell back to the no-Jev flow, and 44/44 questions still got an answer. Missing key: the service still starts, with a single warning line.
- **One weakness remains.** Two-document questions drop from 93% to 73%. The cause is not retrieval: the model merges quotes from two sources into one block tagged with one source id, so it fails verification. A fix is available, see §10.

Reading the tables:

- **Test half** (not used for any tuning): A 95%, B3 95%. **Tuning half**: A 88%, B3 94%. Jev's thresholds were left at their defaults (§9), so both halves are effectively unseen data.
- B1 and B2 score below A on out-of-scope questions: rerank still keeps the 3 "best" passages (even when irrelevant) so the LLM can write its explanation, and the LLM takes the chance to answer. Only the gate cuts this category.
- Each category has only 2–16 questions, so differences below about 10 percentage points are within the model's variance. F-key and F-timeout run the same flow (Jev broken, falling back to A) yet differ by 13 points; that is the noise floor.

## 4. Latency

The A and B runs were tens of minutes apart, and in that window OpenAI throughput moved from 9.4 to 13.8 ms per output token (same model, same answer length). So the latencies in §3 are not directly comparable. The separate measurement below runs **A/B3 interleaved per question, sequentially**, over 16 single-document questions:

| | A | B3 |
|---|---|---|
| Whole-question latency p50 / p95 | 16.6 s / 21.8 s | **14.5 s** / 22.8 s |
| LLM: ms per output token | 18.0 | 18.6 |
| Jev time / question, p50 | – | 1.18 s |

Jev adds about 1 second, but the LLM gets a prompt less than half as long. For questions blocked at the gate, latency drops sharply: 3.7 seconds in the UI, versus 9.5–10.9 seconds when the LLM is called (§7).

## 5. Cost

| Per question | A | B3 |
|---|---|---|
| LLM (`gpt-5-nano`) | $0.00054 | $0.00044 |
| Jev + embedding | ~0 | $0.00035 |
| **Total** | **$0.00054** | **$0.00079** |

Jev charges $0.042 per 1 million input tokens. Rerank sends 20 passages × up to 1,500 characters, so it accounts for most of the cost. With a more expensive Tutor model (e.g. `gpt-5.4-mini`), the LLM token saving would exceed the Jev spend.

## 8. Bugs found and fixed in this run

| Bug | Scope | Measured impact | Fix |
|---|---|---|---|
| Sources were sent to the LLM as JSON: every `"` became `\"`, and the model copied that into its quotes | Present since the old RAG version | Every question about `"w"`, `"x"`, `0.1 + 0.2` was reported as "not in the documents" | `3bc9ac7`: send sources as plain text |
| Quote verification was too strict (case, `**`, backticks, `###`, missing punctuation) | Present since the old RAG version | About 17/18 of the "not in the documents" results were wrong. First run: A 82%, B3 86%; after the fix: A 91%, B3 95% | `de0a54c`: compare the words, ignore formatting; paraphrases are still rejected (tested) |
| The gate read the previous question as part of the request | Jev | Asking about Dijkstra right after an injection attempt was blocked (`unsafe` 0.78), spotted while recording the demo | `31ced6c`: the guardrail judges only `question`; the same pair now gives `in_scope` 0.99 |
| The model merges quotes from two sources into one block with one id | Every mode, more visible on two-document questions | Two-document questions in B3: 73% | Not fixed yet, see §10 |

The first two bugs affected every Tutor user, with or without Jev. They are also the biggest improvement of this run: 82% → 91% before Jev is involved at all.

## 9. Thresholds

Re-swept from the Jev probabilities recorded on the tuning half, with no extra calls:

| `relevant_min` | Recall | Right-passage share | Passages kept on average |
|---|---|---|---|
| 0.2 | 100% | 89% | 2.5 |
| 0.5 (current) | 100% | 94% | 1.9 |
| 0.8 | 100% | 97% | 1.4 |

Recall stays at 100% at every threshold, so there is no evidence yet for moving off 0.5. `sufficient_min` (0.8) could not be swept: in this set, every unanswerable question was already flagged by rerank before reaching the sufficiency step, so there are no negative samples. The threshold stays at its default.

## 10. Recommendations

1. **Merge `feat/tutor-agui` + `feat/tutor-jev`**, and enable Jev with `TYPESAFE_API_KEY` in production.
2. **Verify quotes line by line within a block**: keep the lines that are substrings of the cited source and drop lines from other sources. This fixes the two-source merge (two-document questions at 73%) while keeping the verbatim rule.
3. **Cut rerank cost**: try `RETRIEVE_K` 20 → 12 and `PASSAGE_CHARS` 1500 → 800. On this corpus recall is 100% at every threshold, so this will likely halve the Jev cost; measure again before changing it.
4. **A larger evaluation set before tuning `sufficient_min`**: add "near miss" questions (the document covers the topic but lacks the exact fact asked), so sufficiency has negative samples.
5. **`gpt-5-nano` occasionally inserts stray characters** (a Cyrillic "и" appeared mid-sentence in Vietnamese). Outside Jev's scope, but worth watching.

## 11. Limits of this evaluation

- 44 questions, 14 short documents, one group. Each category has only 2–16 questions, so differences below about 10 percentage points are noise (§3).
- The documents and questions were written by the same author (Claude) and may be easier than real learners' documents. No PDFs yet.
- Rule-based scoring checks sources and quotes but cannot judge the quality of explanations. 6 A/B3 pairs were read by hand (s05, s12, m03, f02, r03, d03): quality is comparable, and B3 answers more directly in a few cases (e.g. in `f02`, A wrote "Timsort is probably stable" although the quote states it definitively).
